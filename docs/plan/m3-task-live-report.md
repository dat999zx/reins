## Findings about the product (all with M3 as built)

- The pause of a failed **subagent** branch does not say `Branch X failed: ...; Resume tries again` (that is core's text for a failed plain turn, in `m3-task-f-run.test.ts`). A subagent step says `the subagent stopped before it answered (<why>); Resume runs it on`. Row 2 asserts the subagent wording; a branch that is a plain phase would say the other.
- A branch pause also writes a `run_paused` row, tagged with `track`, so "the run is not paused" must be read as "no `run_paused` row without the branch's track".
- The run-start check refuses an unknown model of the **session's own** provider (`Unknown model ... not in this session's provider list`) but not one on a second provider, so a failing branch has to name another provider's model. Also, a workflow `usd:` refuses a `<provider>:<model>` step on an unpriced model, so row 2 has no `usd:` (real mode: the CLI cost is the receipt's).
- A track's session id exists in the saved snapshot only while the track lives (a subagent's stays in `subagents`). The test polls the snapshot while the run goes.

## Not deterministic, or not proven

- **Session ids in real mode (rows 1, 4):** read by polling the saved snapshot every 300 ms. A branch that lives under 300 ms could be missed; a CLI or API turn takes seconds, so I expect it to hold, but it is a poll. The dry rows poll every 15 ms and pass.
- **Model wording:** row 1's `final` reply must contain ALPHA and BRAVO, and each branch's reply its own word and not the other's. Haiku may add words; the test asks for one sentence containing the word, which should hold. Row 3 records (does not assert) whether the reply names Ann.
- **Row 2 real:** I could not run `claude --model claude-no-such-model-0`. If the CLI retries or hangs before failing, the 180 s wait for the card times out, and the test fails with a timeout, not a wrong answer. If the CLI accepts the unknown id by falling back to a default, branch `b` would end and the row would fail at "only a ended". The `why` text in the pause is whatever the CLI says; the test only needs 3+ characters in the parentheses.
- **Row 6 real:** "mid-reply" is a turn parked on a tool approval (the same trick as M2 4a), not a model streaming text; a hard kill in the middle of a stream cannot be timed from outside. Requests-after-resume is not counted in real mode.
- **Row 5** uses the HTTP routes of in-process worlds, not the built binary (the task allowed either). The trust prompt of a code mod is tested at the route (preview `codePrompt`, apply `trust` by hash), not in the browser.
- **Cost:** CLI dollars (rows 1, 2) are on the receipt only; the Budget guards the API side. Caps are in the test (`CAPS`); worst case by caps is $0.50 for all six.
- Row 6 is skipped, in dry mode too, when `packages/server/dist/cli.js` does not exist; here it exists (built 17:35, the tree's last commit is docs only).
- The live harness wraps `process.stdout` per world; row 5 starts two worlds and closes them in reverse order so the wrapper chain unwinds.
